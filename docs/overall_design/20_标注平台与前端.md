# 标注平台与前端总体设计

**上位设计**：[系统架构](10_系统架构.md)。**对应需求**：[FR-001～FR-007](../requirements/20_项目与图像标注.md)。

## 1. 职责与边界

| 组件 | 职责及拥有的信息 | 源码依据 |
|---|---|---|
| 项目导航 | 展示项目、状态和类型入口；不管理本地配置写入 | [ProjectDetailPage.tsx](../../frontend/src/pages/ProjectDetailPage.tsx) `ProjectDetailPage` |
| 任务页面 | 将用户输入变为任务结果，处理加载、空队列、提交与错误状态 | [tasks/](../../frontend/src/tasks/) 各 `*ReviewPage` |
| 共享画布 | 视口坐标、框、多边形和栅格编辑，不拥有项目或标签持久化 | [image-canvas/](../../frontend/src/components/image-canvas/) |
| API 与项目注册表 | 校验通用请求，定位项目与模块，映射错误和提供受约束文件读取 | [server.py](../../backend/annotation_platform/server.py) `create_app` |
| 任务模块 | 校验专属配置与输入，管理队列、状态、保存及导出 | [task_types.py](../../backend/annotation_platform/task_types.py) `TaskTypeModule` |

## 2. 协作契约

浏览器经 [client.ts](../../frontend/src/api/client.ts) 调用统一 HTTP API。项目详情和队列包含任务自定义数据，前端任务页按本任务契约解释；通用协议不把内部数据转换成一个巨大的跨任务模型。所有提交必须在后端重新校验，前端输入约束只改善交互体验。

检测使用原图坐标；分割的多边形在浏览器栅格化后与画笔共用同一缓冲区；深度图从基线或空白缓冲区编辑。分割和深度上传最终整图，API 不接收增量笔画。图元契约见[共享画布说明](../../frontend/src/components/image-canvas/README.md)。

## 3. 关键流程与异常

页面读取项目和队列，加载当前样本，生成结果并提交；成功后重新查询队列。空队列展示完成状态，错误显示原因供使用者处理。是否等价重试由服务端判断，提交失败不应靠前端跳过样本来掩盖。跨系统时序见[数据与接口](70_数据与接口.md)。

文件端点只在解析后的项目根目录内读取；这个目录级约束不等同于账户权限或逐文件授权。图像跨域像素读取还依赖浏览器的 CORS 图像规则。

## 4. 扩展与详细设计移交

新增任务需实现必需能力、在 `default_task_types` 注册并提供配置与测试；需要后台动作时才实现可选协议。前端必须在 [App.tsx](../../frontend/src/App.tsx) `App` 和项目详情增加页面入口，没有自动从插件生成 UI 的机制。

字段、错误与导出格式见[外部接口](../detailed_design/70_外部接口.md)；模块契约见[后端详细设计](../detailed_design/20_标注平台后端.md)及[前端详细设计](../detailed_design/40_React前端.md)。

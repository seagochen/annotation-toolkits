# 配置参考

全部配置项的参考表。**具体默认值以对应的 `.example.yaml` 为一次信息源**，本文档
只写名称、作用、约束，不转记数值。

## 1. 工作区与项目注册表

项目只通过 Web 界面管理（创建、修改属性、导入、导出、删除，端点见
[`70_外部接口.md`](70_外部接口.md)"项目管理"）。服务端的全部项目状态都在一个
**工作区**目录（`ANNOTATION_WORKSPACE`，见 §4）里：

```text
<workspace>/
├── projects.yaml                 # 项目注册表（格式见下表），由平台写入
└── projects/
    └── <id>/
        ├── config.yaml           # 该项目的任务配置（§2/§3 的格式），由属性表单写入
        └── data/                 # 托管数据目录：上传/zip 导入的图片、ReID 抽取结果、标注结果
```

- 工作区目录与 `projects.yaml` 都是**第一次写入时才创建**；不存在的工作区就是一个
  空项目列表，不是错误。
- 新项目的 `config.yaml` 里 `dataset: ./data`（相对配置文件，即托管目录）。关联服务器
  目录后 `dataset` 改为该目录的绝对路径，标注结果（`.annotations/` 等）随之写在被关联
  的目录里。
- 注册表条目的 `config` 写成相对 `projects.yaml` 的路径 `projects/<id>/config.yaml`。
- 所有注册表与配置写入都在注册表文件锁下串行、原子替换。
- 兼容：`ANNOTATION_WORKSPACE` 指向一个 `.yaml`/`.yml` 文件（或任何已存在的文件）时，
  该文件本身就是注册表，其所在目录是工作区——手写的注册表（如
  `backend/configs/projects.example.yaml`）仍可直接使用，且可在 Web 上继续管理。
  这种情况下注册表文件不存在会报 `registry_invalid`。

`projects.yaml` 格式（一次信息源：
[`backend/configs/projects.example.yaml`](../../backend/configs/projects.example.yaml)；
经 Web 保存时按 PyYAML 重新序列化，手写注释会丢失）：

| 键 | 作用 | 约束 |
|---|---|---|
| `projects` | 项目条目数组 | 可以为空 |
| `projects[].id` | 项目标识，出现在 URL 和文件路径里 | 全局唯一；Web 创建时由名称生成（`[a-z0-9-]`） |
| `projects[].name` | 展示名 | — |
| `projects[].task_type` | 决定用哪个 `TaskTypeModule` | 必须是已注册的类型名（见下） |
| `projects[].config` | 该任务类型自己的配置文件路径 | 相对 `projects.yaml` 所在目录解析 |

已注册的 `task_type` 值：`reid`、`classification`、`captioning`、`detection`、
`segmentation`、`depth`、`text_span`（见
[`task_types.py`](../../backend/annotation_platform/task_types.py) `default_task_types()`）。
不同项目的数据集根目录不能相同（`ProjectRegistry` 会拒绝）。

## 2. 各任务类型配置

以下任务类型（不含 `reid`，见 §3）共享一部分配置键的语义（"全部"指除 `reid` 外的全部）：

| 键 | 出现在 | 作用 | 约束 |
|---|---|---|---|
| `dataset` | 全部 | 数据集根目录 | 相对配置文件所在目录解析 |
| `patterns` | 全部 | 发现待标注文件的 glob 模式 | 各自有默认值（见对应 example.yaml）；不得指向 dataset 外部。`classification`/`captioning` 匹配到非图片扩展名的文件时按 UTF-8 文本文档处理（如 `**/*.txt`，见 [`70_外部接口.md`](70_外部接口.md)"图像与文本条目"） |
| `annotations` | 全部 | 标注结果落盘位置 | 必须落在 `dataset` 内部；`classification`/`caption`/`detection`/`text_span` 是文件路径，`segmentation`/`depth` 是**目录**路径 |
| `labels` | `classification`、`text_span` | 可选标签集合 | 非空、去重 |
| `mode` | `classification` | `single`（恰好一个）或 `multi`（至少一个） | 只能是这两个值之一 |
| `categories` | `detection`、`segmentation` | 类别集合，顺序即导出 id 顺序 | 非空、去重；`segmentation` 最多 254 个（像素值上限） |
| `depth_maps` | `depth` | 基线深度图目录 | 必须落在 `dataset` 内部，且与 `annotations` 不重叠 |

一次信息源（含默认值）：

- [`backend/configs/classification.example.yaml`](../../backend/configs/classification.example.yaml)
- [`backend/configs/caption.example.yaml`](../../backend/configs/caption.example.yaml)
- [`backend/configs/detection.example.yaml`](../../backend/configs/detection.example.yaml)
- [`backend/configs/segmentation.example.yaml`](../../backend/configs/segmentation.example.yaml)
- [`backend/configs/depth.example.yaml`](../../backend/configs/depth.example.yaml)
- [`backend/configs/text_span.example.yaml`](../../backend/configs/text_span.example.yaml)

`segmentation`/`depth` 的 `annotations`（和 `depth` 的 `depth_maps`）目录会被自动
从 `patterns` 的文件发现范围里排除，见
[`20_标注平台后端.md`](20_标注平台后端.md) §5。

`patterns` 按 `pathlib.Path.glob` 匹配，在 Linux 上**区分大小写**。上传和 zip 导入
会把扩展名统一存成小写（`IMG_0001.JPG` → `IMG_0001.jpg`），因此托管数据目录总能被
默认模式发现；但**关联目录**里的文件保持原名，含大写扩展名时需要在属性表单的
"文件匹配模式"里追加 `**/*.JPG` 等模式。

## 3. ReID 配置：`reid.yaml`

一次信息源：[`backend/configs/reid.example.yaml`](../../backend/configs/reid.example.yaml)。
分节归属（`dataset`/`pipeline`/`extract`/`splits`/`projection`/`crops`/`pairs`/
`mine`/`train`/`evaluate`/`models`）与每节"归谁决定"的说明见 `backend/README.md`
"配置文件"一节（本文档不重复）。校验规则：除 `pipeline`/`models` 外，所有节的键
都对照 `reid_annotation_tool/config.py` 的 `DEFAULTS` 校验，写错键直接报错。

## 4. 环境变量

| 变量 | 作用于 | 默认值 | 约束 |
|---|---|---|---|
| `ANNOTATION_WORKSPACE` | `server.py` | `workspace`（相对当前工作目录） | 工作区目录（§1）；指向 `.yaml`/`.yml` 文件时视为注册表本身。取代旧的 `ANNOTATION_PROJECTS_CONFIG`（已不再读取）。Docker 镜像中为 `/data` |
| `ANNOTATION_IMPORT_ROOTS` | `server.py` | 未设置（只允许关联工作区内的目录） | 以 `os.pathsep`（Linux 为 `:`）分隔的**绝对**路径列表，出现相对路径时启动失败。项目只能关联位于工作区内或这些目录内（含自身，解析符号链接后判断）的服务器目录；工作区的 `projects/` 树及其上级目录始终不可关联。平台无认证且文件端点会提供数据集根目录下的任意文件，因此不要把 `/` 之类的大范围目录放进来 |
| `ANNOTATION_CORS_ORIGINS` | `server.py` | `http://localhost:5173,http://127.0.0.1:5173` | 逗号分隔；不接受 `*` |
| `ANNOTATION_FRONTEND_DIST` | `server.py` | 未设置（不托管前端） | 指向 `vite build` 产物目录（含 `index.html`）；设置后同一进程在 `/api` 之外托管前端，未知页面路径回落到 `index.html`，`/api/*` 与 `/assets/*` 的未知路径仍返回 404。目录不存在时启动失败。Docker 镜像中为 `/app/frontend` |
| `PORT` | `docker/entrypoint.sh` | `3000` | 仅容器内：`uvicorn` 监听端口 |
| `VITE_API_BASE_URL` | 前端（`frontend/src/api/client.ts`） | `window.location.origin` | 前后端分开部署时需要显式设置 |

本项目不使用 `.env` 文件；上述变量在进程启动时通过 shell `export` 或部署环境注入，
见 [`90_部署与运维.md`](90_部署与运维.md)。

# 部署与运维

## 1. 安装

后端与前端是两个独立进程，各自安装依赖：

```bash
# 后端：只审核/检查/定版和运行五个视觉任务类型，不需要视频抽取/训练依赖
pip install -e 'backend[test]'

# 需要 ReID 的视频抽取、候选挖掘（含参考检测流水线）时
pip install -e 'backend[extract,ultralytics]'

# 前端
cd frontend && npm install
```

无凭证/密钥需要配置——本平台没有认证体系（见
[`10_通用设计.md`](10_通用设计.md) §3）。

## 2. 启动

```bash
export ANNOTATION_PROJECTS_CONFIG=backend/configs/projects.example.yaml
uvicorn annotation_platform.server:app --app-dir backend --reload
```

```bash
cd frontend && npm run dev
```

两个命令行的完整参数、CORS 跨域配置见 [`80_配置参考.md`](80_配置参考.md) §4 与
根 [`README.md`](../../README.md) 快速开始。前后端分开部署（不同主机/端口）时，
除了 `ANNOTATION_CORS_ORIGINS` 要包含前端来源，深度任务读取基线图的 `<img>` 还
依赖 `crossOrigin`（见 [`10_通用设计.md`](10_通用设计.md) §3），这一点已经在前端
代码里处理，不需要额外部署配置。

## 3. 打包

前端生产构建：

```bash
cd frontend && npm run build
```

产物是静态文件，可用任意静态文件服务器托管；需要在构建时或运行时设置
`VITE_API_BASE_URL` 指向实际的后端地址。后端没有专门的打包步骤——`pip install`
一个可编辑或非可编辑安装即可，用生产级 ASGI 服务器（如 `uvicorn`/`gunicorn +
uvicorn worker`）启动 `annotation_platform.server:app`。

## 4. 停启

- 后端：`uvicorn` 进程，标准 `SIGTERM`/`Ctrl+C` 停止；ReID 后台任务用线程执行
  （见 [`30_ReID流水线.md`](30_ReID流水线.md) §4），进程终止时未完成的任务不会
  继续，下次启动加载任务历史时会被标记为 `failed`（"interrupted: platform
  restarted"）。
- 前端：开发服务器同理；生产构建是静态文件，停启由托管方决定。

## 5. 日常运维

- **备份**：所有状态都是本地文件（JSON 侧车、CSV、PNG），标准文件系统备份策略
  即可，无需数据库层面的运维。
- **日志**：ReID 后台任务的日志写在 `Job.log` 里，随任务历史一起持久化在
  `<dataset>/.jobs/`；`uvicorn` 自身的访问日志走标准输出。
- **清理**：项目配置错误或数据集迁移后，直接编辑/替换对应的 YAML 配置和
  `annotations` 目录即可，没有需要显式"清缓存"的中间状态。
- **监控**：`GET /api/projects/{id}` 的 `status` 字段（`missing`/`empty`/
  `reviewing`/`reviewed`）是最直接的健康信号，见
  [`70_外部接口.md`](70_外部接口.md)。

# 配置参考

全部配置项的参考表。**具体默认值以对应的 `.example.yaml` 为一次信息源**，本文档
只写名称、作用、约束，不转记数值。

## 1. 项目注册表：`projects.yaml`

一次信息源：[`backend/configs/projects.example.yaml`](../../backend/configs/projects.example.yaml)。

| 键 | 作用 | 约束 |
|---|---|---|
| `projects` | 项目条目数组 | 至少一项 |
| `projects[].id` | 项目标识，出现在 URL 和文件路径里 | 全局唯一 |
| `projects[].name` | 展示名 | — |
| `projects[].task_type` | 决定用哪个 `TaskTypeModule` | 必须是已注册的类型名（见下） |
| `projects[].config` | 该任务类型自己的配置文件路径 | 相对 `projects.yaml` 所在目录解析 |

已注册的 `task_type` 值：`reid`、`classification`、`captioning`、`detection`、
`segmentation`、`depth`（见
[`task_types.py`](../../backend/annotation_platform/task_types.py) `default_task_types()`）。
不同项目的数据集根目录不能相同（`ProjectRegistry` 会拒绝）。

## 2. 各任务类型配置

以下五个任务类型（不含 `reid`，见 §3）共享一部分配置键的语义：

| 键 | 出现在 | 作用 | 约束 |
|---|---|---|---|
| `dataset` | 全部五种 | 数据集根目录 | 相对配置文件所在目录解析 |
| `patterns` | 全部五种 | 发现待标注文件的 glob 模式 | 各自有默认值（见对应 example.yaml）；不得指向 dataset 外部 |
| `annotations` | 全部五种 | 标注结果落盘位置 | 必须落在 `dataset` 内部；`classification`/`caption`/`detection` 是文件路径，`segmentation`/`depth` 是**目录**路径 |
| `labels` | `classification` | 可选标签集合 | 非空、去重 |
| `mode` | `classification` | `single`（恰好一个）或 `multi`（至少一个） | 只能是这两个值之一 |
| `categories` | `detection`、`segmentation` | 类别集合，顺序即导出 id 顺序 | 非空、去重；`segmentation` 最多 254 个（像素值上限） |
| `depth_maps` | `depth` | 基线深度图目录 | 必须落在 `dataset` 内部，且与 `annotations` 不重叠 |

一次信息源（含默认值）：

- [`backend/configs/classification.example.yaml`](../../backend/configs/classification.example.yaml)
- [`backend/configs/caption.example.yaml`](../../backend/configs/caption.example.yaml)
- [`backend/configs/detection.example.yaml`](../../backend/configs/detection.example.yaml)
- [`backend/configs/segmentation.example.yaml`](../../backend/configs/segmentation.example.yaml)
- [`backend/configs/depth.example.yaml`](../../backend/configs/depth.example.yaml)

`segmentation`/`depth` 的 `annotations`（和 `depth` 的 `depth_maps`）目录会被自动
从 `patterns` 的文件发现范围里排除，见
[`20_标注平台后端.md`](20_标注平台后端.md) §5。

## 3. ReID 配置：`reid.yaml`

一次信息源：[`backend/configs/reid.example.yaml`](../../backend/configs/reid.example.yaml)。
分节归属（`dataset`/`pipeline`/`extract`/`splits`/`projection`/`crops`/`pairs`/
`mine`/`train`/`evaluate`/`models`）与每节"归谁决定"的说明见 `backend/README.md`
"配置文件"一节（本文档不重复）。校验规则：除 `pipeline`/`models` 外，所有节的键
都对照 `reid_annotation_tool/config.py` 的 `DEFAULTS` 校验，写错键直接报错。

## 4. 环境变量

| 变量 | 作用于 | 默认值 | 约束 |
|---|---|---|---|
| `ANNOTATION_PROJECTS_CONFIG` | `server.py` | `projects.yaml`（相对当前工作目录） | — |
| `ANNOTATION_CORS_ORIGINS` | `server.py` | `http://localhost:5173,http://127.0.0.1:5173` | 逗号分隔；不接受 `*` |
| `VITE_API_BASE_URL` | 前端（`frontend/src/api/client.ts`） | `window.location.origin` | 前后端分开部署时需要显式设置 |

本项目不使用 `.env` 文件；上述变量在进程启动时通过 shell `export` 或部署环境注入，
见 [`90_部署与运维.md`](90_部署与运维.md)。

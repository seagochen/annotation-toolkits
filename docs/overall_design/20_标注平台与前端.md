## 2. 协作契约

浏览器经 [client.ts](../../frontend/src/api/client.ts) 调用统一 HTTP API。项目详情和队列包含任务自定义数据，前端任务页按本任务契约解释；通用协议不把内部数据转换成一个巨大的跨任务模型。所有提交必须在后端重新校验，前端输入约束只改善交互体验。

文本由后端严格按 UTF-8 解码后随队列条目下发，浏览器不猜测编码；文本片段的位置以 code point 计，与后端字符串下标一致。检测使用原图坐标；分割的多边形在浏览器栅格化后与画笔共用同一缓冲区；深度图从基线或空白缓冲区编辑。分割和深度上传最终整图，API 不接收增量笔画。图元契约见[共享画布说明](../../frontend/src/components/image-canvas/README.md)。

## 3. 关键流程与异常

页面读取项目和队列，加载当前样本，生成结果并提交；成功后重新查询队列。空队列展示完成状态，错误显示原因供使用者处理。是否等价重试由服务端判断，提交失败不应靠前端跳过样本来掩盖。跨系统时序见[数据与接口](70_数据与接口.md)。

文件端点只在解析后的项目根目录内读取；这个目录级约束不等同于账户权限或逐文件授权。正因为文件端点会提供数据集根目录下的任意文件，关联目录被限制在工作区与 `ANNOTATION_IMPORT_ROOTS` 内，上传只接受任务声明的文件类别，并按扩展名所属类别校验内容（图片签名、UTF-8 文本或 JSON）。图像跨域像素读取还依赖浏览器的 CORS 图像规则。

## 4. 扩展与详细设计移交

新增任务需实现必需能力、在 `default_task_types` 注册并提供配置与测试；需要后台动作时才实现可选协议；要能在浏览器中创建，还需在 `project_forms.py` 描述其属性表单。前端必须在 [project-meta.ts](../../frontend/src/project-meta.ts) `taskEntries` 与 [App.tsx](../../frontend/src/App.tsx) `App` 增加页面入口；属性表单按 `/api/task-types` 的字段描述通用渲染，任务页面没有自动从插件生成 UI 的机制。

字段、错误与导出格式见[外部接口](../detailed_design/70_外部接口.md)；模块契约见[后端详细设计](../detailed_design/20_标注平台后端.md)及[前端详细设计](../detailed_design/40_React前端.md)。

# 外部接口

本平台只有一套 HTTP API（[`server.py`](../../backend/annotation_platform/server.py)），
对全部任务类型通用；本文档也是唯一允许写具体字段值和示例的地方（其余文档一律引用
回这里）。项目**只通过这套 API（即 Web 界面）管理**：创建、修改属性、导入数据、导出、
删除都有对应端点，不再需要手写 `projects.yaml`（工作区布局见
[`80_配置参考.md`](80_配置参考.md) §1）。`TaskTypeModule.export()` 通过
`GET /api/projects/{id}/export` 以下载形式提供。

默认监听 `127.0.0.1:8000`，接口文档见 `http://127.0.0.1:8000/docs`（FastAPI 自动生成）。

## 端点一览

| 方法 & 路径 | 说明 |
|---|---|
| `GET /api/projects` | 列出全部项目 |
| `GET /api/projects/{id}` | 单个项目详情 |
| `GET /api/projects/{id}/queue` | 队列分页查询 |
| `POST /api/projects/{id}/annotations` | 提交一个 item 的标注结果 |
| `GET /api/projects/{id}/actions` | 列出支持的动作与历史任务 |
| `POST /api/projects/{id}/actions/{action}` | 启动一个后台动作 |
| `GET /api/projects/{id}/actions/jobs/{job_id}` | 查询后台任务状态 |
| `GET /api/projects/{id}/files/{path}` | 读取项目根目录下的文件 |
| `GET /api/task-types` | 可创建的任务类型及其属性表单定义 |
| `POST /api/projects` | 创建项目 |
| `GET /api/projects/{id}/settings` | 项目属性（表单值、原始配置、数据来源） |
| `PUT /api/projects/{id}/settings` | 按表单修改名称/属性 |
| `PUT /api/projects/{id}/config` | 用原始 YAML 整体替换任务配置 |
| `DELETE /api/projects/{id}` | 删除项目 |
| `POST /api/projects/{id}/import/files?path=` | 上传单个文件（图片，或该任务接受的文本/JSON）到托管数据目录 |
| `POST /api/projects/{id}/import/archive` | 上传 zip 并解出其中该任务接受的文件 |
| `POST /api/projects/{id}/import/directory` | 关联服务器上已有的目录作为数据集 |
| `GET /api/projects/{id}/export?format=` | 下载导出产物 |

## 通用错误响应

所有错误响应体形状一致：

```json
{ "detail": { "code": "task_conflict", "message": "..." } }
```

`code` 的取值见 [`10_通用设计.md`](10_通用设计.md) §2。

## `GET /api/projects`

返回 `ProjectListItem[]`：

```json
[{ "id": "scene-detection", "name": "Scene Detection", "task_type": "detection", "root": "/abs/path", "status": "reviewing" }]
```

`status` 取值：`missing`（数据集目录不存在）、`empty`（无可标注文件）、`reviewing`
（有未完成 item）、`reviewed`（全部完成）；ReID 额外有 `needs_mining`。

## `GET /api/projects/{id}`

返回 `ProjectDetail`：在 `ProjectListItem` 基础上加 `summary`（任务自定义字典，
字段因任务类型而异，见下）。404 时 `code: project_not_found`。

## `GET /api/projects/{id}/queue`

查询参数：`offset`（默认 0）、`limit`（默认 60，1–`MAX_QUEUE_LIMIT`=200，常量在
`task_types.py`）、`status`、`q`。`status`/`q` 是所有任务类型都支持的平台级过滤
（`q` 为路径子串，不区分大小写；`status` 对 ReID 以外的任务只接受 `pending` 与
`annotated`，ReID 接受 `pending` 与 `same`/`different`/`unclear`）；其他
查询参数原样作为 `QueueRequest.filters` 交给任务模块，由模块接受或以 422 拒绝（平台
不认识任何任务专属过滤名）。目前只有 ReID 另外接受 `kind`、`split`。返回 `QueueResponse`：

```json
{ "total": 12, "offset": 0, "limit": 60, "items": [ /* 任务自定义字典数组，见下 */ ] }
```

除 ReID 外，每个 item 在下文的任务字段之外还带 `annotated`（布尔）：该条目是否已有
保存的结果（`ImageTaskStore.queue()` 统一添加）。不带 `status` 过滤读取全部条目时，
前端的图像列表据此标出已完成的条目——空的检测结果（`boxes: []`）同样算已完成，所以
不能从任务字段推断。

## `POST /api/projects/{id}/annotations`

请求体 `AnnotationRequest`：`{ "item_id": "...", "result": { /* 任务自定义 */ } }`。
成功返回 `AnnotationResponse`：`{ "item": {...}, "status": { "state": "...", "details": {...} } }`。
409 = 与已保存结果冲突（`code: task_conflict`；`polygon` 为基于旧版本的修改），422 = 校验失败。

## 各任务类型的 `result` / `item` / `summary` 形状

### 图像与文本条目（classification / captioning 共用）

这两个任务的数据源既可以是图片，也可以是 UTF-8 文本文档（短评论、长文章均可），
由配置的 `patterns` 决定，没有单独的开关：匹配到的文件扩展名是
`.jpg`/`.jpeg`/`.png`/`.webp` 时按图片处理，其他扩展名一律按文本处理
（`backend/annotation_platform/file_kinds.py` `media_kind()`）。默认 `patterns` 只匹配
图片；标注文本时改为 `**/*.txt` 等。

`queue().items[]` 在任务字段之外带上：

| 字段 | 含义 |
|---|---|
| `image_path` | 数据集相对**源文件**路径。名称沿用图片时代，文本条目里同样是该文本文件的路径 |
| `media` | `image` 或 `text` |
| `text` | 仅文本条目：后端按 UTF-8 严格解码后的全文；去掉开头的 BOM，**换行符原样保留**（`\r\n` 不归一化） |
| `text_error` | 仅文本条目：无法读取时的原因（不是合法 UTF-8、含 NUL 字节、超过 2 MiB `MAX_DOCUMENT_BYTES`），此时 `text` 为 `null`；可读时为 `null` |

前端按 `media` 渲染：图片用 `<img>`，文本用可滚动的文本视图（保留空白与换行）；
`text_error` 原样显示，不做编码猜测。无法读取的文本条目拒绝提交（422，消息包含文件名
与原因），因此任何结果都对应一份确实展示过的文本。

### classification

`summary`：`{ "mode": "single"|"multi", "labels": [...] }`。`queue().items[]` 每项：
`{ "item_id", "image_path", "media", "labels": string[] }`（文本条目另有 `text`/`text_error`）。
提交 `result`：

```json
{ "labels": ["outdoor"] }
```

约束：`labels` 必须全部在配置的 `labels` 内、不重复；`single` 模式恰好一个，
`multi` 模式至少一个；保存时按配置声明顺序重排。导出（`GET .../export?format=`）：
`format=native|json`（原样返回 JSON 侧车）、`format=csv`（`item_id,image_path,labels`）。

### captioning

`summary`：`{}`（无任务专属字段）。`queue().items[]`：
`{ "item_id", "image_path", "media", "caption": string }`（文本条目另有 `text`/`text_error`）。
对文本条目，`caption` 就是为该文档写出的自由文本（翻译、摘要等）。提交 `result`：

```json
{ "caption": "一只猫在窗边睡觉。" }
```

约束：`\r\n`/`\r` 归一化为 `\n`，首尾裁剪；裁剪后为空一律拒绝；长度上限：图片条目
2000 字符（`MAX_CAPTION_LENGTH`），文本条目 20000 字符（`MAX_GENERATED_TEXT_LENGTH`），
均按裁剪后计数。导出：`format=native|json`、`format=csv`
（`item_id,image_path,caption`）。

### text_span

span/区间标注（#40）：每个条目是一份 UTF-8 文本文档（默认 `patterns` 为 `**/*.txt`），
结果是带标签的半开区间列表。`summary`：`{ "labels": string[] }`。`queue().items[]`：
`{ "item_id", "image_path", "media": "text", "text", "text_error", "spans": Span[] }`
（`text`/`text_error` 同"图像与文本条目"）。提交 `result`：

```json
{ "spans": [
  { "start": 0, "end": 2, "label": "PER" },
  { "start": 0, "end": 9, "label": "EVENT" }
] }
```

| 规则 | 内容 |
|---|---|
| offset 编码 | **Unicode code point**，即后端 Python 字符串下标；`text` 就是被索引的字符串（去 BOM，换行原样保留）。前端在 UTF-16 与 code point 间换算（`frontend/src/img-annotation/standard/text-span/text-span.ts` `CodePointIndex`），emoji 等代理对字符计为 1 |
| 区间 | 半开区间 `[start, end)`，必须满足 `0 <= start < end <= len(text)`；`start`/`end` 必须是整数（`true`、`1.0`、`"1"` 都拒绝） |
| 重叠 / 嵌套 | 任意重叠、嵌套均允许；完全相同的 `(start, end, label)` 出现两次拒绝 |
| 跨段落 | 允许，不额外限制 |
| `label` | 必须在配置的 `labels` 内 |
| 规范化 | 保存时按 `start`、`end`、`labels` 中的顺序排序；空 `spans` 是合法提交（"没有需要标注的内容"） |
| 幂等 / 冲突 | 同 FR-007：等价结果重复提交成功且不追加历史，不同结果 409 |

保存的 item 另带 `length`（提交时文档的 code point 数），用来在文档事后被修改时判断
offset 是否仍然对应原文。无法解码的文档拒绝提交（422）。

导出（`GET .../export?format=`）：只有 `format=native|json`，原样返回 JSON 侧车
（`schema`/`items`/`history`，`items[<item_id>] = { "image_path", "length", "spans" }`）。
NER 训练常用的 `conll`/`jsonl` 等格式待确认真实消费场景后再加。

`start`/`end` 的语义不与"字符"绑定：`text_span_task._spans()` 只按条目长度做边界检查，
将来的音频/视频时间区间标注可以沿用同一区间形状（本次未实现）。

### detection

`summary`：`{ "categories": string[] }`。`queue().items[]`：
`{ "item_id", "image_path", "boxes": Box[] }`。提交 `result`（坐标为原图像素坐标，
左上角为 `(0,0)`）：

```json
{
  "image_size": { "width": 1920, "height": 1080 },
  "boxes": [{ "category": "person", "x": 120, "y": 80, "width": 60, "height": 140 }]
}
```

约束：`image_size` 的 `width`/`height` 必须是正整数，首次提交固定下来；`box` 越界
（超出 `image_size`）、宽高非正、`category` 不在配置内一律拒绝（HTTP 422），不做
静默裁剪；空 `boxes` 列表是合法提交（"确认没有目标"）。

导出（`GET .../export?format=`）：`format=native|json`；`format=coco` 写出 `coco.json`
（`category_id` 按配置 `categories` 顺序从 1 编号，`image_id`/`annotation.id` 按
item/box 排序确定性生成，`image_size` 序列化为整数，`bbox`/`area` 为浮点数；
`info.version` 为导出契约，见"导出契约"）：

<!-- export-example: detection-coco/v1 -->
```json
{
  "info": { "description": "Annotation Toolkits detection-coco export", "version": "detection-coco/v1" },
  "images": [{ "id": 1, "file_name": "a.jpg", "width": 1920, "height": 1080 }],
  "categories": [{ "id": 1, "name": "person" }, { "id": 2, "name": "vehicle" }],
  "annotations": [{ "id": 1, "image_id": 1, "category_id": 1, "bbox": [120.0, 80.0, 60.0, 140.0], "area": 8400.0, "iscrowd": 0 }]
}
```

### segmentation

`summary`：`{ "categories": string[] }`（像素值 `1..N` 对应第 `1..N` 个类别，`0` 恒为
背景）。`queue().items[]`：`{ "item_id", "image_path", "mask_path", "image_size" }`
（未标注时后两者为 `null`）。提交 `result`——**整图栅格替换**，不是增量笔画或多边形
顶点（前端的多边形/画笔都只是作画方式，见 [`20_标注平台后端.md`](20_标注平台后端.md) §5）：

```json
{ "image_size": { "width": 640, "height": 480 }, "pixels": "<base64，width*height 字节>" }
```

约束：`pixels` 解码后长度必须恰好等于 `width*height`；像素值不能超过配置的类别数；
幂等判定用像素 sha256；不一致的重复提交拒绝为 409。

导出（`GET .../export?format=`）：`format=native`（`index.json` + 各 item 的掩膜 PNG 路径）；
`format=coco` 写出 `coco.json`，`segmentation` 字段是**掩膜文件路径引用**，不是
RLE/polygon 编码（"COCO 兼容"而非完整实现；需要标准 COCO 多边形时用 `polygon` 任务）：

<!-- export-example: segmentation-coco/v1 -->
```json
{
  "info": { "description": "Annotation Toolkits segmentation-coco export", "version": "segmentation-coco/v1" },
  "images": [{ "id": 1, "file_name": "a.jpg", "width": 640, "height": 480 }],
  "categories": [{ "id": 1, "name": "road" }, { "id": 2, "name": "building" }],
  "annotations": [{ "image_id": 1, "segmentation_mask": "<item_id>.png" }]
}
```

掩膜文件本身通过 `GET /api/projects/{id}/files/.annotations/segmentation/<item_id>.png`
读取，是一张真实的 8-bit 灰度 PNG。

### polygon

可编辑的矢量标注（#41）：多边形、矩形框、关键点本身就是结果（与分割不同，分割的
多边形只是作画方式），同一张图可以混合三种形状。类别完全由项目配置决定（至少 1 类），
三种形状共用同一组类别，平台不赋予任何类别特殊语义。框与关键点是后加的：侧车
`schema` 2 起才有；`schema` 1 的侧车（只有多边形）照常读取，下次保存或原生导出时
整体改写为 `schema` 2（每个 item 补上空的 `boxes`/`points`），读取本身从不写文件。

`summary`：`{ "categories": string[], "prelabels": string|null }`；配置了 `prelabels`
时另有 `prelabel_images`（已加载预标的图像数）、`prelabel_issue_count`（未加载条目
总数）、`prelabel_issues`（前 200 条，每条 `{ "file_name", "image_id", "annotation_id",
"reason" }`，未知的字段为 `null`）；预标文件整体不可用时为 `prelabel_error`，项目
`state` 为 `invalid`。

`queue().items[]`：

| 字段 | 含义 |
|---|---|
| `item_id` / `image_path` | 同其他图像任务 |
| `revision` | 已保存结果的版本号；未提交为 `0` |
| `source` | 初始内容来源：`annotation`（已提交结果）、`prelabel`（预标）、`none`（空白） |
| `image_size` | 已保存结果或预标的 `{width, height}`；都没有时为 `null` |
| `polygons` / `boxes` / `points` | 同提交格式；`source` 为 `none` 时为空数组 |

提交 `result`（坐标为原图像素坐标）：

```json
{
  "image_size": { "width": 1920, "height": 1080 },
  "base_revision": 0,
  "polygons": [{ "category": "material", "points": [[120, 80], [300, 80], [300, 260]] }],
  "boxes": [{ "category": "crack", "x": 400, "y": 120, "width": 80, "height": 40 }],
  "points": [{ "category": "material", "x": 640, "y": 360 }]
}
```

约束：每个多边形恰好有 `category`/`points` 两个字段，`points` 至少 3 个 `[x, y]`；每个框
恰好有 `category`/`x`/`y`/`width`/`height`，宽高为正、整个框在图内；每个关键点恰好有
`category`/`x`/`y`；`category` 必须在配置内；坐标为有限数并落在
`[0, width] × [0, height]` 内（含边界）。`boxes`/`points` 可省略（视为空列表，旧客户端
照常可用）；三个列表都可以为空（"该图没有目标"，有效结果）；列表按提交顺序保存。
`image_size` 必须与已加载的预标或已保存结果的尺寸一致。非法提交 422，不保存。

**修订规则**（与 FR-007 的"不同结果即冲突"不同，见需求 FR-019）：

| 情形 | 结果 |
|---|---|
| 与当前结果等价（多边形、框、关键点三个列表都相同） | 幂等成功，不增加版本、不追加历史（不论 `base_revision`） |
| `base_revision` 等于当前版本（未提交为 0） | 覆盖，`revision` + 1，`history` 追加一条（含 `base_revision`），旧版本保留在历史中 |
| `base_revision` 不等于当前版本 | 409 `task_conflict`（页面基于旧状态），不覆盖 |

**预标导入**（`prelabels`，可选，数据集内的标准 COCO 文件，只读）：

- 每条 annotation 按内容成为一种形状（`iscrowd` 缺省或为 `0`）：
  - 有 `keypoints`：一个关键点，只接受单点 `[x, y, v]`，`v` 为 `1` 或 `2`；
  - 有非空 `segmentation: [[x1, y1, x2, y2, ...], ...]`：多边形，每个环各成为一个多边形；
  - `segmentation` 缺省或为 `[]`：一个框，取 `bbox: [x, y, w, h]`（正尺寸、在图内）。

  因此本任务导出的 COCO 可以原样作为另一个项目的预标。
- `images[].file_name` 按数据集相对路径匹配图像；`annotations[].category_id` 经
  `categories[]` 换成名称，按名称匹配配置的 `categories`。
- **以图像为单位判定**：某张图只要有一条 annotation 不合法（未知类别、RLE、
  `iscrowd: 1`、点数不足、越界、非有限值、多点 keypoints、未标注的关键点），该图的预标整体不加载、从空白开始；
  `file_name` 对不上任何图像、`id` 或 `file_name` 重复、缺少正整数 `width`/`height` 的
  image 条目及其 annotation 同样不加载；不指向任何 image 条目的 annotation 单独报告。
  合法的图照常加载；只有 image 条目、没有 annotation 的图以"没有目标"加载。
- 所有未加载条目与原因都在 `summary.prelabel_issues` 中，项目详情页以表格显示。
- 文件不存在、不是 UTF-8 JSON、缺少 `images`/`annotations`/`categories` 列表、
  `categories` 条目缺少整数 id/名称或重复时，项目不可用：队列、提交、COCO 导出均 422，
  `state` 为 `invalid`；其他项目与项目列表不受影响。
- 预标文件可在导入页上传（`.json`，按 JSON 校验），平台从不修改它，也不把它当作源图。

导出（`GET .../export?format=`）：`format=native|json` 返回 JSON 侧车
（`polygon-json/v2`：`schema: 2`，`items[<item_id>] = { "image_path", "image_size",
"polygons", "boxes", "points", "revision" }`，`history` 含每一版；侧车还是 `schema` 1 时
先就地升级再返回）；`format=coco` 写出 `.annotations/polygon.coco.json`，为**标准 COCO**
（`polygon-coco/v2`）：

<!-- export-example: polygon-coco/v2 -->
```json
{
  "info": { "description": "Annotation Toolkits polygon-coco export", "version": "polygon-coco/v2" },
  "images": [{ "site": "north", "id": 1, "file_name": "a.jpg", "width": 1920, "height": 1080 }],
  "annotations": [
    { "id": 1, "image_id": 1, "category_id": 1,
      "segmentation": [[120.0, 80.0, 300.0, 80.0, 300.0, 260.0]],
      "area": 16200.0, "bbox": [120.0, 80.0, 180.0, 180.0], "iscrowd": 0 },
    { "id": 2, "image_id": 1, "category_id": 2, "segmentation": [],
      "area": 3200.0, "bbox": [400.0, 120.0, 80.0, 40.0], "iscrowd": 0 },
    { "id": 3, "image_id": 1, "category_id": 1, "segmentation": [], "area": 0.0,
      "bbox": [640.0, 360.0, 0.0, 0.0], "keypoints": [640.0, 360.0, 2], "num_keypoints": 1, "iscrowd": 0 }
  ],
  "categories": [
    { "id": 1, "name": "material", "keypoints": ["point"], "skeleton": [] },
    { "id": 2, "name": "crack", "keypoints": ["point"], "skeleton": [] }
  ]
}
```

只包含已提交的图像（按 `image_path` 排序，`image_id` 从 1 编号）；`category_id` 按配置
顺序从 1 编号；每张图依次是每个多边形、每个框、每个关键点各一条 annotation，`id`
连续编号：

- 多边形：一个 `segmentation` 环，`area` 为鞋带公式面积，`bbox` 为外接框；
- 框：`segmentation: []`，`area = w * h`；
- 关键点：`keypoints: [x, y, 2]`（2 = 可见）、`num_keypoints: 1`、`bbox: [x, y, 0, 0]`、
  `area: 0`、`segmentation: []`。每个类别都声明 `keypoints: ["point"]` 与空 `skeleton`，
  按 COCO 关键点格式读取的训练框架可以直接使用。

预标文件里 `images[]` 的额外字段（除 `id`/`file_name`/`width`/`height` 外）原样透传到
对应图像。导出文件可直接作为另一个 `polygon` 项目的 `prelabels`。

从 v1 升级（破坏性变更）：v1 的每条 annotation 都是多边形，v2 起可以是框或关键点
（`segmentation` 为空），原生侧车多了 `boxes`/`points` 且 `schema` 为 2。只认多边形的
下游需要按上面的规则区分三种 annotation。v1 契约仍保留在
`annotation_platform.exports check` 中，用于校验升级前导出的文件。

### depth

`summary`：`{}`。`queue().items[]`：
`{ "item_id", "image_path", "baseline_path", "depth_path", "image_size" }`
（`baseline_path` 是该 item 对应的基线深度图相对路径，没有基线时为 `null`；
`depth_path`/`image_size` 未标注时为 `null`）。提交 `result`——同样是**整图栅格
替换**（画笔的"提高/降低"语义完全是前端交互，提交的是最终整图栅格）：

```json
{ "image_size": { "width": 640, "height": 480 }, "pixels": "<base64，0-255 灰度值>" }
```

约束同 segmentation（长度校验、像素 sha256 幂等），但没有类别数上限（任意 0–255
合法）。导出（`GET .../export?format=`）：只支持 `format=native`（`index.json` + 各 item 的
编辑后深度图 PNG 路径）；深度图不是结构化标注，没有 COCO 等价物。

基线图与编辑结果都通过文件端点读取：

```bash
curl http://127.0.0.1:8000/api/projects/{id}/files/.depth-baseline/a.png
curl http://127.0.0.1:8000/api/projects/{id}/files/.annotations/depth/<item_id>.png
```

### reid

`summary`：见 `backend/README.md`（ReID 的 `Project.summary()`）。`queue().items[]`：
候选对字段（`candidate_id`、`person_id1`/`person_id2`、`gallery1`/`gallery2` 等）。
提交 `result`：

```json
{ "label": "same", "notes": "clear" }
```

`label` 取值 `same`/`different`/`unclear`；`notes` 可选。导出：只支持
`format=native`，返回当前 `pairs.csv`。ReID 额外暴露 `TaskActionModule` 六个后台
动作（`extract`/`mine`/`check`/`finalize`/`purge-domain`/`train`），通过
`POST /api/projects/{id}/actions/{action}` 启动、`GET .../actions/jobs/{job_id}`
轮询；各动作接受的 `options` 布尔开关见 `backend/README.md`。

## 导出契约（版本化）

每个可下载的 `(任务类型, format)` 对应一个**导出契约**，由
[`export_contracts.py`](../../backend/annotation_platform/export_contracts.py) 的
`CONTRACTS` 唯一定义：契约名（即模块返回的 `ExportResult.format`）+ 版本号 + 校验器。
`native` 与 `json` 是同一契约的两个别名。

- **每次导出都先校验再下载**：`Workspace.export()` 用契约校验模块产出的文件，不符合时
  返回 500 `export_invalid`，不会把不合规的文件交给使用者。下载响应头
  `X-Export-Contract` 给出契约 ID；`/api/task-types` 的每个 `export_formats[]` 也带
  `contract` 字段。
- **版本规则**：删除/改名字段、改变单位或编码属于破坏性变更，必须升版本（`/v2`）；
  新增可选字段不升版本。JSON 侧车的 `schema`、COCO 的 `info.version` 与契约版本一致，
  CSV 以表头为准并由响应头标明契约。
- **确定性**：同一项目状态的两次导出逐字节相同（id 按固定顺序生成，多文件 zip 的
  条目顺序与文件时间戳都来自已落盘的文件）。

| 契约 | 产生方式 | 文件 | 校验要点 |
|---|---|---|---|
| `classification-json/v1` | classification `native`/`json` | JSON 侧车 | `schema: 1`；`items[item_id] = {image_path, labels: string[]}` |
| `classification-csv/v1` | classification `csv` | `item_id,image_path,labels` | 表头一致；`labels` 为 JSON 字符串数组 |
| `caption-json/v1` | captioning `native`/`json` | JSON 侧车 | `items[item_id] = {image_path, caption}` |
| `caption-csv/v1` | captioning `csv` | `item_id,image_path,caption` | 表头一致 |
| `text-span-json/v1` | text_span `native`/`json` | JSON 侧车 | `items[item_id] = {image_path, length, spans}`；整数 code point，`0 <= start < end <= length` |
| `detection-json/v1` | detection `native`/`json` | JSON 侧车 | `image_size` 为正整数；`boxes` 为有限数 |
| `detection-coco/v1` | detection `coco` | `coco.json` | COCO 结构、id 唯一且引用存在；`bbox` 正尺寸、`area = w*h`、`iscrowd: 0` |
| `segmentation-masks/v1` | segmentation `native`/`json` | zip：`index.json` + 掩膜 PNG | 索引项 `mask_path`/`pixel_hash`；PNG 文件与索引一一对应且为 PNG |
| `segmentation-coco/v1` | segmentation `coco` | `coco.json` | COCO 结构；annotation 的 `segmentation_mask` 引用掩膜文件 |
| `polygon-json/v2` | polygon `native`/`json` | JSON 侧车（`schema: 2`） | `revision >= 1`；多边形至少 3 个有限数点；框正尺寸且在图内；关键点在图内 |
| `polygon-coco/v2` | polygon `coco` | `polygon.coco.json` | 标准 COCO：多边形 annotation 一个环、点在图内、`area` 为鞋带公式面积、`bbox` 为外接框；框 `segmentation: []`、`area = w*h`；关键点 `[x, y, 2]`、`bbox: [x, y, 0, 0]`、类别声明 `keypoints: ["point"]`；`iscrowd: 0` |
| `polygon-json/v1`（旧版） | 不再产生，仅 `check` | JSON 侧车（`schema: 1`） | `revision >= 1`；多边形至少 3 个有限数点 |
| `polygon-coco/v1`（旧版） | 不再产生，仅 `check` | `polygon.coco.json` | 标准 COCO：每条 annotation 一个环、点在图内、`area` 为鞋带公式面积、`bbox` 为外接框、`iscrowd: 0` |
| `depth-maps/v1` | depth `native`/`json` | zip：`index.json` + 深度 PNG | 索引项 `depth_path`/`baseline_path`/`pixel_hash`；PNG 与索引一一对应 |
| `reid-pairs-csv/v1` | reid `native` | 当前 pairs 清单 | 表头为 `PAIR_FIELDS`；`label` 为 `0`/`1` |

## 项目管理

以下端点的错误同样是 `{"detail": {"code", "message"}}`。通用约定：未知项目 404
`project_not_found`；输入非法 422；与现有状态冲突 409；`projects.yaml` 本身无法读取
时 500 `registry_invalid`。写操作（创建、改属性、改配置、关联目录、删除）在注册表
文件锁下串行执行，配置与注册表都是原子替换。

### `GET /api/task-types`

返回 `TaskTypeInfo[]`，顺序固定为 classification、captioning、text_span、detection、
segmentation、polygon、depth、reid（只列出当前服务注册了的类型）：

```json
[{
  "type": "detection", "label": "目标检测", "description": "在图片上用矩形框标出每个目标并指定类别。",
  "import_modes": ["upload", "directory"],
  "upload_extensions": [".jpeg", ".jpg", ".png", ".webp"],
  "export_formats": [{ "format": "native", "label": "原生 JSON" }, { "format": "coco", "label": "COCO" }],
  "fields": [{
    "key": "categories", "label": "类别", "type": "list", "required": true, "default": null,
    "options": null, "help": "…", "lock": "append_only", "server_only": false, "group": null
  }]
}]
```

`FieldSpec` 字段：

| 字段 | 含义 |
|---|---|
| `key` | 指向任务配置 YAML 的点分路径（`pipeline.script` 即 `pipeline: {script: …}`） |
| `type` | `text`/`path`/`integer`/`number`/`boolean`/`select`/`list`（`list` 为字符串数组） |
| `required` / `default` | 必填与默认值；`default` 也是配置里缺省该键时的实际值 |
| `options` | `select` 的可选值 `[{value, label}]`，其余类型为 `null` |
| `lock` | 项目**已有标注**后的修改限制：`append_only` = 新列表必须以旧列表开头（只能在末尾追加；分割像素值、COCO `category_id` 都按列表位置编号），`locked` = 不能再改；`none` 无限制 |
| `server_only` | 只读展示；通过 API 修改会被拒绝（`server_only_field`）。这些键指向平台会执行的程序（训练器/评估器目录及其 Python 解释器），在无认证的 HTTP API 上可改就等于远程代码执行，只能在服务器上直接编辑配置文件。ReID 另有几个不在表单里、同样只能在服务器上改的键，见原始配置端点 |
| `group` | 表单分组名（如 `高级`、`流水线`），`null` 为不分组 |

`import_modes`：`upload`（上传文件/zip 到托管目录）、`directory`（关联服务器目录）、
`managed`（仅 ReID：从空的托管目录开始，由 `extract` 动作填充）。

`upload_extensions`：`upload` 模式接受的扩展名（小写、带点、排序）；不支持上传时为空
数组。图片任务只接受图片；`classification`/`captioning` 另接受 `.txt`/`.md` 文本；
`text_span` 只接受 `.txt`/`.md` 文本；`polygon` 另接受 `.json`（预标文件）。
前端导入页据此过滤和提示，服务端以 `TaskTypeSpec.upload_kinds` 为准。

各任务类型的表单字段：

| 任务类型 | 字段 |
|---|---|
| classification | `labels`（必填，append_only）、`mode`（`single`/`multi`，默认 `single`，locked）、`patterns`（高级） |
| captioning | `patterns` |
| text_span | `labels`（必填，append_only）、`patterns`（默认 `**/*.txt`） |
| polygon | `categories`（必填，append_only）、`prelabels`（可选，数据集内 COCO 文件的相对路径）、`patterns` |
| detection / segmentation | `categories`（必填，append_only）、`patterns` |
| depth | `depth_maps`（数据集相对的基线深度图目录，默认 `.depth-baseline`）、`patterns` |
| reid | `pipeline.script`（`ultralytics`/`tracking_csv`）、`pipeline.detector`、`pipeline.reid_onnx`、`pipeline.device`、`extract.videos_dir`、`extract.pattern`、`extract.frame_stride`、`mine.reid_onnx`、`mine.min_cosine`、`mine.per_split`、`train.name`、`evaluate.checkpoint`；server_only：`train.trainer`、`train.python`、`evaluate.evaluator`、`evaluate.python` |

### `POST /api/projects`

请求体 `CreateProjectRequest`：

```json
{ "name": "街景检测", "task_type": "detection", "settings": { "categories": ["person", "car"] } }
```

成功返回 201 + `ProjectDetail`（同 `GET /api/projects/{id}`）。项目 id 由名称生成：
小写 ASCII（`[a-z0-9-]`，其他字符折叠为 `-`，去掉首尾 `-`），名称里没有可用字符
（如纯中文）时为任务类型名（如 `detection`）；重名依次加 `-2`、`-3`…。服务端写出
`<workspace>/projects/<id>/config.yaml`（`dataset: ./data`，未提交的字段写入默认值）
和空的 `data/` 目录，再用任务模块 `load()` 校验，最后追加注册表条目。

| 状态码 / `code` | 场景 |
|---|---|
| 422 `invalid_name` | 名称去空白后为空，或超过 200 字符 |
| 422 `unknown_task_type` | 未注册或不可在 Web 上创建的任务类型 |
| 422 `unknown_setting` / `invalid_setting` / `missing_setting` | 表单键不存在 / 类型不符 / 必填缺失 |
| 422 `server_only_field` | 提交了 server_only 键的值 |
| 422 `path_not_allowed` | 模型/权重路径指向 `<workspace>/projects/` 内部（见下） |
| 422 `invalid_config` | 任务模块拒绝了生成的配置（`message` 为模块原文，如分割类别超过 254 个） |

任何失败都会删除已创建的目录，注册表保持不变。

**模型/权重路径规则**：`pipeline.detector`、`pipeline.reid_onnx`、`mine.reid_onnx`、
`evaluate.checkpoint` 以及每个 `models.<name>.path` 的新值（相对路径按配置文件所在
目录解析、解析符号链接后）不能落在 `<workspace>/projects/` 内部（创建、表单修改、
原始配置三条路径都检查；未改动的旧值不检查）。该目录是 HTTP 客户端唯一能写入自选
内容的地方，而 torch 权重是 pickle，加载即执行代码；其他位置的路径照常可改。

### `GET /api/projects/{id}/settings`

返回 `ProjectSettingsResponse`：

```json
{
  "id": "street", "name": "街景检测", "task_type": "detection",
  "values": { "categories": ["person", "car"], "patterns": ["**/*.jpg", "…"] },
  "fields": [ /* FieldSpec[]，同 /api/task-types */ ],
  "config_path": "/data/projects/street/config.yaml",
  "config_text": "dataset: ./data\ncategories:\n- person\n…",
  "data_source": { "mode": "managed", "path": "/data/projects/street/data" },
  "import_roots": ["/data", "/mnt/datasets"],
  "annotated": false
}
```

- `values`：每个字段的当前值，配置里没有该键时为字段默认值。
- `data_source.mode`：数据集根目录正是 `<workspace>/projects/<id>/data` 时为
  `managed`，否则为 `directory`（关联目录，以及手写注册表时代的项目）。
- `import_roots`：允许关联的目录根，第一个恒为工作区自身，其后是
  `ANNOTATION_IMPORT_ROOTS`（见 [`80_配置参考.md`](80_配置参考.md) §4）。
- `annotated`：项目是否已有标注（图像任务为 `total - pending > 0`，ReID 为当前轮
  `labelled > 0`），决定 `lock` 规则是否生效。

### `PUT /api/projects/{id}/settings`

请求体 `{ "name"?: string, "settings"?: { "<点分键>": 值 } }`，返回同上。`settings`
合并进现有 YAML（表单不认识的键原样保留；值为 `null` 或空字符串表示删除该键、回到
默认值）；与当前值相同的键直接忽略，因此把整张表单原样回传是安全的。写入前先在同
目录写临时文件并用任务模块 `load()` 校验，通过后原子替换。注意：经表单保存会按
PyYAML 重新序列化，**配置文件里的注释会丢失**；需要保留注释时用原始配置端点。

| 状态码 / `code` | 场景 |
|---|---|
| 422 `invalid_name` / `unknown_setting` / `invalid_setting` / `missing_setting` | 同创建 |
| 422 `server_only_field` | 修改了 server_only 键 |
| 422 `path_not_allowed` | 模型/权重路径指向 `<workspace>/projects/` 内部（见下） |
| 409 `setting_locked` | 项目已有标注，且违反了字段的 `append_only`/`locked` 规则 |
| 422 `invalid_config` | 任务模块拒绝了合并后的配置 |

### `PUT /api/projects/{id}/config`

请求体 `{ "text": "<完整 YAML>" }`，返回同上。文本校验通过后**原样写入**（保留注释
和排版）。额外规则：

- 必须解析为 YAML 映射，否则 422 `invalid_config`；
- `dataset`、`annotations` 两个键的原始值必须与当前完全相同，否则 422
  `protected_setting`（数据位置只能经导入/关联端点改变）；
- server_only 键不能改，ReID 的 `pipeline.script` 只能改成内置名称
  （`ultralytics`/`tracking_csv`）或保持原值，否则 422 `server_only_field`；ReID 的
  `extract.out`、`mine.output_dir`（改变动作写到哪里）和 `train.set`、
  `train.base_config`、`evaluate.set`、`evaluate.base_config`（改写外部训练器/评估器
  自己的配置）同样不能改（缺省、空字符串、空列表视为同一值）；
- 模型/权重路径不能新设为 `<workspace>/projects/` 内部的路径，否则 422
  `path_not_allowed`（规则见下）；
- 已有标注时同样执行 `lock` 规则（409 `setting_locked`）；
- 最后由任务模块 `load()` 校验（422 `invalid_config`）。

### `DELETE /api/projects/{id}`

成功返回 204。先移除注册表条目，再删除 `<workspace>/projects/<id>/` 整个目录（托管
项目的图片与标注结果都在其中）。关联目录永远不会被删除——关联项目的标注结果
（`.annotations/` 等）留在被关联的目录里。配置文件不在
`<workspace>/projects/<id>/config.yaml` 的项目（手写注册表时代的项目）只移除注册表
条目，不删除任何文件。

### `POST /api/projects/{id}/import/files?path=<相对路径>`

请求体为文件原始字节（`Content-Type: application/octet-stream`），服务端流式写入
同目录临时文件后原子改名；同路径已有文件时覆盖。扩展名统一存为小写
（`IMG_0001.JPG` → `IMG_0001.jpg`，与默认 `patterns` 一致；与已有文件同名时同样覆盖）。
返回规范化后的路径：`{ "path": "day1/IMG_0001.jpg", "size": 10240 }`。

| 状态码 / `code` | 场景 |
|---|---|
| 422 `upload_not_supported` | ReID 项目（数据由 `extract` 动作生成，或关联已有目录） |
| 409 `not_managed` | 项目使用关联目录 |
| 422 `invalid_path` | 路径为空、以 `/` 开头、含 `\`、空段、`..`，或任一段以 `.` 开头（保护 `.annotations` 等平台目录） |
| 422 `unsupported_file` | 扩展名不在该任务的 `upload_extensions` 内（不区分大小写），或内容与扩展名所属类别不符：图片的文件头必须是 JPEG（`FF D8 FF`）、PNG（`89 50 4E 47 0D 0A 1A 0A`）、WebP（`RIFF....WEBP`）三种签名之一（三者任一即可，不要求与扩展名一致）；文本（`.txt`/`.md`）必须是合法 UTF-8 且不含 NUL 字节；JSON（`.json`，仅 `polygon` 的预标文件）必须是可解析的 UTF-8 JSON |
| 422 `empty_file` | 请求体为空 |

### `POST /api/projects/{id}/import/archive`

请求体为 zip 原始字节（`Content-Type: application/zip`），先流式落到项目目录下的临时
文件，再解出其中该任务接受的条目到托管数据目录（保留 zip 内的相对路径）。目录条目忽略；
`__MACOSX`、隐藏段、`..`/绝对路径（zip-slip）、不在 `upload_extensions` 内的扩展名、
内容与扩展名不符（判定同单文件上传）、损坏或加密的条目都跳过并计数，被跳过的条目
不会留下空目录；扩展名同样存为小写。返回 `{ "imported": 120, "skipped": 3 }`。错误：同上的 `upload_not_supported`/
`not_managed`，以及 422 `invalid_archive`（不是可读的 zip）。

### `POST /api/projects/{id}/import/directory`

请求体 `{ "path": "/mnt/datasets/street" }`，把该目录（解析符号链接后的绝对路径）
写入配置的 `dataset` 并经任务模块校验，返回 `ProjectSettingsResponse`
（`data_source.mode` 变为 `directory`）。ReID 项目以此指向一个已抽取好的数据集目录。

| 状态码 / `code` | 场景 |
|---|---|
| 422 `path_not_allowed` | 不在工作区内、也不在 `ANNOTATION_IMPORT_ROOTS` 任一目录内；或是工作区的 `projects/` 目录本身、其内部或其上级目录。先于存在性检查，不泄露其他目录是否存在 |
| 422 `invalid_directory` | 不是绝对路径，或不是已存在的目录 |
| 409 `managed_data_present` | 项目仍是托管模式且 `data/` 里已有文件（关联目录模式的项目可以随时重新关联） |
| 409 `dataset_in_use` | 该目录已是另一个项目的数据集根目录 |
| 422 `invalid_config` | 任务模块拒绝了新配置 |

限制关联范围的原因：平台没有认证，而 `GET /api/projects/{id}/files/...` 会提供数据集
根目录下的任意文件，关联 `/` 就等于公开整台服务器。

### `GET /api/projects/{id}/export?format=<fmt>`

`format` 默认 `native`，可选值见 `/api/task-types` 的 `export_formats`。调用任务模块
`export()`：只有一个产物文件时直接下载，文件名 `<id>-<format><扩展名>`（如
`street-coco.json`）；有多个产物时（分割/深度的 `native`：`index.json` + 各 PNG）
打包为 `<id>-<format>.zip`，zip 内路径相对数据集根目录（如
`.annotations/segmentation/index.json`），临时 zip 在响应发送后删除。响应头
`Content-Disposition: attachment; filename="…"`。模块拒绝（不支持的格式、ReID 尚无
pairs 文件等）为 422 `export_failed`。
